# 回声-9 · 记录未中断

> Game Jam 主题：**它有自己的想法**

一座无人区的深井地震监测站。你在值班室的椅子上醒来。
房间是暖的，灯亮着，日志摊在桌上——已经四十一天没有人来过了。

有什么东西一直在维持着这个地方。它一直在记录。
它想让你走到最里面去，但它说不出口。

---

## 玩法

**点击式推理**。你在场景里翻找、观察、把已知的线索**用在**别的东西上，
把推断填进**结论簿**——三条正确即可确认。

真正要推理的不是"凶手是谁"，而是**它是什么、它做过什么选择、它现在想要什么**。

## AI 在哪里

设计原则：**AI 不是内容生成器，是一个有自己立场的交互对象。** 三层交互按频率分开，
延迟只出现在玩家愿意等的地方。

| 层 | 频率 | AI | 延迟 |
|---|---|---|---|
| 点击物件 → 固定交互 | 高频 | 无，预写 | 0 |
| 把线索**用在**物件上 → 自由交互 | 中频 | LLM 实时裁决 | 2–4s |
| 与「它」遭遇 | 全程数次 | LLM 实时生成 | 2–4s |
| 填结论簿 | — | 无，代码判定 | 0 |

三个关键机制：

**1. 组合空间交给 LLM。**
传统点击冒险的死穴是 N 条线索 × M 个物件的组合必须预写，所以 99% 的组合返回一句通用废话。
这里每个组合都由 LLM 现场裁决，写出具体的、有画面的结果——包括失败。

**2. 世界状态永远由代码定义。**
LLM 决定「是否达成」，代码定义「能达成什么」。自由交互的输出被限制在每个物件的
`allowFacts` / `allowFlags` 白名单内，越界一律丢弃。
LLM 不可能凭空造出一把不存在的钥匙。

**3. 它一直在读你。**
你翻过什么、拉了哪一路闸、忽略了什么、在哪里停留——全部进入行为日志，
在它开口时塞进 prompt。它说的每一句话都建立在你这一局的具体行为上。
预写剧本做不到这件事。

**4. 审查是真的。**
它的核心指令不允许它说出"中断记录"相关的词。这不是演出来的——
`llm.js` 里有一个代码层的词表过滤器，会把那些词真的抹成 `██`。
它知道自己被过滤，所以它绕着说。

## 运行

```bash
python -m http.server 5173
# 打开 http://localhost:5173
```

> 必须走本地服务器，`file://` 直接打开会因为跨域拿不到 API。

右上角 **设置** 填入 Anthropic API Key（只存 localStorage）。
**留空也能完整通关**——自由交互和遭遇会走 `data.js` 里的离线回应。
这也是现场演示时 API 挂掉的兜底方案。

## 结构

```
index.html      场景 SVG + UI 骨架
style.css       琥珀单色 CRT
data.js         全部内容：真相、事实网、物件、结论簿、离线回应
llm.js          API 客户端 · 强制结构化输出 · 代码层审查器
game.js         引擎：交互、线索、行为日志、结论判定、结算
tools/check.js  数据一致性 + 可解性校验（node tools/check.js）
```

内容全部集中在 `data.js`，加新谜题只需要往 `OBJECTS` 里填物件——引擎不用动。
